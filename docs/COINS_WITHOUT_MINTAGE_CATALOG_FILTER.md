# Монеты без числового тиража и вывод в каталог

## В чём была проблема

Скрипт **`scripts/export-coins-to-json.js`** формирует `public/data/coins.json` и карточки **`public/data/coins/<id>.json`** для сайта. Долгое время в каталог попадали **не все** строки из таблицы `coins`.

### Старое правило (до исключения `GB-ROYAL-*`)

Монета попадала в экспорт, если выполнялось **хотя бы одно** условие:

1. **Есть числовой тираж:** `mintage IS NOT NULL` и `mintage <> 0`.
2. **Иностранная монета с текстовым тиражом:** страна не Россия **и** заполнено поле **`mintage_display`** (например, «Неограниченный тираж», «до 50 000» и т.п.).

Если у монеты **не было числа в `mintage`** и **не было подходящего `mintage_display`** (пусто / NULL), запись **не попадала** в статический каталог — на сайте её не было, хотя строка в БД могла существовать.

Типичный случай: **bullion The Royal Mint** на странице товара часто **не дублирует тираж числом** в том виде, как мы кладём в `mintage` после парсера (`mintage` остаётся `NULL`). При этом **`mintage_display`** тоже может быть пустым → монета отфильтровывалась.

### Новое правило (текущий код)

К двум пунктам выше добавлено **третье** условие:

3. **`catalog_number` начинается с `GB-ROYAL-`** — так помечаются монеты, импортированные из **`import-royal-mint-to-db.js`** (парсинг `data/royal-mint-*.json`).

Итоговая логика в коде:

```text
в каталог ⇐ числовой mintage
        ИЛИ (иностранная + непустой mintage_display)
        ИЛИ catalog_number LIKE 'GB-ROYAL-%'
```

## Что изменилось и что появится на сайте

| Изменение | Результат на сайте |
|-----------|-------------------|
| В **`export-coins-to-json.js`** добавлено условие **`GB-ROYAL-*`** | Монеты Royal Mint из импорта с таким `catalog_number` **появляются в каталоге** и на странице **`/coins/<id>/`**, даже если **`mintage` = NULL** и **`mintage_display` пустой**. |
| Остальная логика экспорта без изменений | Российские и прочие иностранные монеты ведут себя как раньше (числовой тираж или текстовый для иностранных). |
| Добавлен **`import-royal-mint-to-db.js`** + **`npm run royal-mint:import`** | Имеющийся JSON с Royal Mint можно загрузить в БД и после **`npm run data:export`** увидеть монеты в каталоге. |

**Важно:** на карточке по-прежнему отображаются поля из БД. Если **`mintage` и `mintage_display` пустые**, блок тиража на сайте может не показываться или показываться как «—» — это ожидаемо, пока не заполните данные вручную или парсер не начнёт вытаскивать тираж в эти поля.

## Отдельный список монет «без тиража по старому правилу»

Снимок **из вашей БД** мы в репозиторий не кладём: состав монет у каждого окружения свой.

Чтобы получить **актуальный список** записей, которые **раньше не проходили** в каталог только из‑за тиража (без учёта нового `GB-ROYAL-*`), выполните SQL из файла:

**`scripts/sql/list-coins-excluded-by-mintage-filter-before-gb-royal.sql`**

Результат можно сохранить в CSV / в `data/` у себя локально, например:

```bash
mysql -u USER -p DATABASE < scripts/sql/list-coins-excluded-by-mintage-filter-before-gb-royal.sql > data/coins-no-mintage-excluded-from-catalog.tsv
```

(подставьте свои параметры подключения.)

В этом списке могут быть не только Royal Mint, но и любые другие строки `coins` без числового `mintage` и без заполненного `mintage_display` (в т.ч. тестовые или черновики).

## Поиск монет без тиража и подсказки с сайта

Скрипт **`scripts/report-coins-missing-mintage.js`** (или `npm run coins:report-missing-mintage`):

- выбирает из БД записи, где **нет числового `mintage`** и **пустой `mintage_display`**;
- пишет отчёт **`data/coins-missing-mintage-report.json`** (id, название, `source_url`, каталожный номер и т.д.);
- с флагом **`--probe`** для URL на **royalmint.com** / **perthmint.com** делает HTTP-запрос и ищет в HTML строки вроде **Mintage** / **Maximum Mintage** (эвристика, не гарантия).

Примеры:

```bash
npm run coins:report-missing-mintage
npm run coins:report-missing-mintage -- --probe --limit 20
```

## Связанные команды

- Импорт RM в БД: `npm run royal-mint:import`
- Экспорт в `public/data`: `npm run data:export` или `npm run data:export:incremental`
- Парсинг одной монеты: `npm run royal-mint:fetch-test`

## Кратко

- **«Без тиража»** в контексте фильтра = **нет числа в `mintage`** и **нет спасающего `mintage_display`** для иностранных монет.
- Раньше такие записи **не попадали в JSON каталога**.
- Сейчас монеты с **`catalog_number` вида `GB-ROYAL-…`** **всегда попадают** в экспорт после `data:export`.
- Полный перечень таких монет в **вашей** базе — через SQL в `scripts/sql/list-coins-excluded-by-mintage-filter-before-gb-royal.sql`.
