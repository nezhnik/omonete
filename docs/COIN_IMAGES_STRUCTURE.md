# Структура изображений монет

Изображения монет лежат в `public/image/coins/` и разделены по папкам:

## Папки

| Папка | Назначение |
|-------|------------|
| `ru/` | Российские монеты (ЦБ РФ, каталог: 3213-XXXX, 5109-XXXX, 5111-XXXX и т.д.) |
| `foreign/` | Иностранные монеты (США, Канада, Австралия и др.) |

## Пути в БД

В колонках `image_obverse` и `image_reverse` хранятся полные пути:

- Российские: `/image/coins/ru/5111-0178-26.webp`, `/image/coins/ru/5111-0178-26r.webp`
- Иностранные: `/image/coins/foreign/US-ASE-2021-BU.webp` или внешние URL (например, ucoin CDN)

## Скрипты

- **download-dzi-coins-by-base.js**, **download-dzi-coins.js** — качают с ЦБ РФ → `ru/`
- **download-and-optimize-coins.js**, **download-cbr-images.js** — скачивание изображений ЦБ → `ru/`
- **chervonets-images-to-webp.js** — конвертирует PNG червонцев → `ru/`
- **set-chervonets-image-paths.js** — прописывает пути червонцев в БД → `ru/`
- **check-missing-coin-images.js** — проверка наличия файлов в `ru/`
- **trim-coin-images.js** — обрезка белых полей в `ru/`
- **migrate-coins-images-to-folders.js** — миграция: перемещает файлы в `ru/` и обновляет БД

## Добавление новых изображений

**Российские:** положить в `public/image/coins/ru/`, имена по `catalog_number` (например `5111-0178-26.webp`, `5111-0178-26r.webp`).

**Иностранные:** положить в `public/image/coins/foreign/` или использовать внешние URL (ucoin, ЦБ др. стран).

## Масштаб отображения в UI (каталог и страница монеты)

**Когда нужно:** в webp/png вокруг монеты большой «воздух» (поля, прозрачность по краям). В карточке каталога стоит `object-contain` и фиксированный холст — монета **визуально меньше** соседей (типичный пример: 2 oz рядом с 1 oz при одинаковой высоте кадра).

**Правильный способ (как для монеты `6404`):** не трогать файлы и не менять общие стили карточки — добавить **точечный коэффициент по `id` монеты** из экспорта (тот же id, что в URL `/coins/<id>/`).

### Шаги

1. **Узнать id** монеты (из URL или из `public/data/coins/<id>.json`).
2. **Открыть** `lib/coinCatalogImageScale.ts`.
3. **В каталог** — в объект `COIN_CATALOG_CARD_IMAGE_SCALE` добавить строку `"<id>": <число>` (например `1.18`–`1.25`). Число — множитель `transform: scale(...)` для главного кадра в карточке.
4. **На странице монеты** — при необходимости то же id в `COIN_DETAIL_MAIN_IMAGE_SCALE` с чуть **меньшим** коэффициентом (холст там уже крупнее), например на ~0.08–0.1 меньше, чем в каталоге.
5. **Компоненты уже подключены:**  
   - `components/CoinCard.tsx` — масштаб задаётся на **элементе `<img>`**, не на внешнем блоке с `lg:group-hover:-translate-y-2`, иначе inline `transform` перебьёт hover-сдвиг. Снаружи остаётся обёртка с `overflow-hidden` и прежним скруглением.  
   - `components/CoinDetail.tsx` — масштаб на главном `<img>` галереи, класс `origin-center`.
6. **Проверка:** каталог (рядом с «эталонной» карточкой) и `/coins/<id>/`. Подобрать коэффициент «на глаз», пока диаметр монеты совпадает с ожиданием.

### Альтернатива (другая задача)

Если нужно **физически убрать поля из файла** (меньший файл, единый вид без исключений в коде) — см. скрипт **`trim-coin-images.js`** в списке выше. UI-масштаб и trim не исключают друг друга, но для одной монеты обычно достаточно одного подхода.
